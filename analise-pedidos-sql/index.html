A base

Uma view com o que importa de cada entrega

Pedidos com status "entregue" e todas as datas preenchidas, já com a duração de cada etapa (aprovação, postagem e transporte) e a marcação de entrega no prazo. Registros com postagem anterior à aprovação foram descartados. Todas as perguntas partem desta view.

Ver a view em SQL
CREATE VIEW vw_entregas AS
SELECT
    o.order_id,
    c.customer_state                                   AS uf_cliente,
    DATE(o.order_purchase_timestamp)                   AS data_compra,
    STRFTIME('%Y-%m', o.order_purchase_timestamp)      AS mes,
    JULIANDAY(o.order_approved_at)            - JULIANDAY(o.order_purchase_timestamp)     AS dias_aprovacao,
    JULIANDAY(o.order_delivered_carrier_date) - JULIANDAY(o.order_approved_at)            AS dias_postagem,
    JULIANDAY(o.order_delivered_customer_date)- JULIANDAY(o.order_delivered_carrier_date) AS dias_transporte,
    JULIANDAY(o.order_delivered_customer_date)- JULIANDAY(o.order_purchase_timestamp)     AS lead_time,
    JULIANDAY(DATE(o.order_delivered_customer_date)) - JULIANDAY(DATE(o.order_estimated_delivery_date)) AS dias_vs_prazo,
    CASE WHEN DATE(o.order_delivered_customer_date) <= DATE(o.order_estimated_delivery_date)
         THEN 1 ELSE 0 END                             AS no_prazo
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
WHERE o.order_status = 'delivered'
  AND o.order_approved_at              IS NOT NULL
  AND o.order_delivered_carrier_date   IS NOT NULL
  AND o.order_delivered_customer_date  IS NOT NULL
  AND o.order_estimated_delivery_date  IS NOT NULL
  AND o.order_delivered_carrier_date  >= o.order_approved_at;   -- descarta registros com datas invertidas

Onde o tempo de entrega é gasto?

04

Quando o vendedor posta depois do limite, o atraso aumenta?

3,9x mais atraso

Sim: 20,8% de atraso contra 5,4% de quem posta dentro do limite, quase 4 vezes mais. Só 9,2% dos pedidos estão nesse grupo, então é um problema pequeno e fácil de atacar.

Consulta SQL
WITH limite AS (
    SELECT order_id, MIN(shipping_limit_date) AS limite_postagem
    FROM order_items
    GROUP BY order_id
)
SELECT
    CASE WHEN o.order_delivered_carrier_date > l.limite_postagem
         THEN 'Postou depois do limite' ELSE 'Postou dentro do limite' END AS postagem,
    COUNT(*)                                     AS pedidos,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS pct_dos_pedidos,
    ROUND(100.0 * (1 - AVG(e.no_prazo)), 1)      AS pct_entregue_atrasado
FROM vw_entregas e
JOIN orders o ON o.order_id = e.order_id
JOIN limite l ON l.order_id = e.order_id
GROUP BY postagem
ORDER BY pct_entregue_atrasado DESC

Consulta SQL
WITH rota AS (
    SELECT DISTINCT e.order_id, s.seller_state || ' → ' || e.uf_cliente AS rota, e.no_prazo, e.lead_time
    FROM vw_entregas e
    JOIN order_items i ON i.order_id = e.order_id
    JOIN sellers s     ON s.seller_id = i.seller_id
)
SELECT
    rota,
    COUNT(*)                               AS pedidos,
    ROUND(100.0 * (1 - AVG(no_prazo)), 1)  AS pct_atraso,
    ROUND(AVG(lead_time), 1)               AS lead_time_medio
FROM rota
GROUP BY rota
HAVING COUNT(*) >= 500
ORDER BY pct_atraso DESC
LIMIT 8

Consulta SQL
WITH por_uf AS (
    SELECT
        uf_cliente,
        COUNT(*)                                AS pedidos,
        ROUND(100.0 * (1 - AVG(no_prazo)), 1)   AS pct_atraso,
        ROUND(AVG(lead_time), 1)                AS lead_time_medio
    FROM vw_entregas
    GROUP BY uf_cliente
    HAVING COUNT(*) >= 300
)
SELECT
    RANK() OVER (ORDER BY pct_atraso DESC) AS ranking,
    uf_cliente, pedidos, pct_atraso, lead_time_medio
FROM por_uf
ORDER BY ranking
LIMIT 10

O atraso derruba a satisfação do cliente?

4,28 → 1,69

A nota cai de 4,28 para 1,69 quando o atraso passa de 7 dias, e 79% desses clientes dão nota 1 ou 2. Um a três dias de atraso já tiram um ponto inteiro da nota.

Consulta SQL
WITH nota AS (
    SELECT order_id, AVG(review_score) AS nota
    FROM order_reviews
    GROUP BY order_id
)
SELECT
    CASE
        WHEN e.dias_vs_prazo <= 0  THEN '1. No prazo'
        WHEN e.dias_vs_prazo <= 3  THEN '2. 1 a 3 dias de atraso'
        WHEN e.dias_vs_prazo <= 7  THEN '3. 4 a 7 dias de atraso'
        ELSE                            '4. Mais de 7 dias de atraso'
    END                                         AS faixa,
    COUNT(*)                                    AS pedidos,
    ROUND(AVG(n.nota), 2)                       AS nota_media,
    ROUND(100.0 * AVG(CASE WHEN n.nota <= 2 THEN 1.0 ELSE 0 END), 1) AS pct_notas_1_ou_2
FROM vw_entregas e
JOIN nota n ON n.order_id = e.order_id
GROUP BY faixa
ORDER BY faixa

Consulta SQL
SELECT
    CASE
        WHEN dias_vs_prazo <= -15 THEN '1. 15+ dias antes do prazo'
        WHEN dias_vs_prazo <= -8  THEN '2. 8 a 14 dias antes'
        WHEN dias_vs_prazo <= -1  THEN '3. 1 a 7 dias antes'
        WHEN dias_vs_prazo  =  0  THEN '4. No dia do prazo'
        ELSE                           '5. Depois do prazo'
    END                                              AS chegada,
    COUNT(*)                                         AS pedidos,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS pct
FROM vw_entregas
GROUP BY chegada
ORDER BY chegada

Recomendações

O que eu faria com esses números

01Atacar a postagem fora do limite

São só 9% dos pedidos, mas com quase 4 vezes mais atraso. Alertar o vendedor perto do limite e acompanhar quem reincide tem retorno rápido.

02Revisar o transporte nas rotas críticas

SP → RJ e os destinos do Nordeste concentram o atraso. Vale comparar transportadoras e prazos por rota.

03Ajustar o prazo prometido

A estimativa tem folga demais. Prometer menos dias onde a operação entrega com sobra pode ajudar na conversão sem piorar o nível de serviço.

04Planejar os picos

Black Friday e o início de 2018 derrubaram o nível de serviço. Capacidade extra e comunicação de prazo nesses meses evitam a queda na nota.
